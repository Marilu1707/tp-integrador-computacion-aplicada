# =============================================================================
#  Crontab de root — Backups automáticos (consigna 5.7)
# =============================================================================
#  Cómo cargarlo:  como root, ejecutar "crontab -e", pegar las 2 líneas de
#  abajo (las que no empiezan con #) al final, guardar y salir.
#  Verificar con:  crontab -l
#
#  Formato de cada línea (5 campos de tiempo + el comando):
#
#   ┌──────── minuto        (0-59)
#   │ ┌────── hora          (0-23)
#   │ │ ┌──── día del mes   (1-31)
#   │ │ │ ┌── mes           (1-12)
#   │ │ │ │ ┌ día de semana (0-7; 0 y 7 = domingo, 1 = lunes ... 5 = viernes)
#   │ │ │ │ │
#   * * * * *  comando
#
#   "*" = "cualquier valor" (todos los días, todos los meses, etc.).
#   "1,3,5" = lista de valores (lunes, miércoles y viernes).
#
#  ">> /var/log/backup_full.log 2>&1": guarda la salida del script en un log.
#     >>    agrega al final del archivo (no lo pisa)
#     2>&1  manda también los errores (canal 2) al mismo lugar que la salida (1)
#  Así, si un backup falla de madrugada, después se puede ver por qué.
#
#  Nota: la consigna dice "/var/logs", pero en Debian el directorio de logs es
#  /var/log (sin "s"); el ejemplo de la propia consigna lo confirma
#  ("log_bkp_20240302.tar.gz"). Usamos /var/log.
# =============================================================================

# TODOS LOS DÍAS a las 00:00 → backup de /var/log
0 0 * * * /opt/scripts/backup_full.sh /var/log /backup_dir >> /var/log/backup_full.log 2>&1

# LUNES, MIÉRCOLES y VIERNES a las 23:00 → backup de /www_dir
0 23 * * 1,3,5 /opt/scripts/backup_full.sh /www_dir /backup_dir >> /var/log/backup_full.log 2>&1
